# EASy68K Functional Parity Audit

**Goal:** full functional parity with the original Windows-only EASy68K
(Sim68K, Edit68K, EASyBIN, Help) as a cross-platform Qt 6 application set.

**Method:** every user-visible element was extracted from the original Borland
forms (`*.dfm`: menus, actions, shortcuts, dialogs, options) and cross-checked
against the original sources and the port. Each item has a parity ID, the
original source, the current port status, and the plan task that delivers it.
Items without a task in the original execution plan are marked **NEW** and are
added to the plan below.

**Policy:** parity means the original's functionality, not its bugs: bugs and
algorithmic inefficiencies found in the original are fixed (and documented as
deviations); no functional improvements are added.

Status legend: **Done** (implemented and tested in the port), **Partial**,
**Gap** (planned, not implemented), **NEW** (missing from the plan; added here).

**Verification.** Assembler items are checked against a *reference oracle*:
the original Edit68K assembler core built on Linux from the original sources
(`tools/reference/edit68k`, `easy68k-ref-asm`). Golden data under
`data/golden/asm` is generated by the oracle, never by the port. Simulator
items are checked the same way against the original Sim68K core built headless
(`tools/reference/sim68k`, `easy68k-ref-sim`): `tools/reference/compare_sim.sh`
runs a program in both and diffs every instruction's registers, the memory
hash and the program output.
